# Test scope report template

## 分析范围

- 模式：Mode A（仅代码变更）/ Mode B（需求对照）
- 变更来源：工作区 / 暂存区 / commit / range / PR / patch
- 覆盖范围：已深入检查的模块
- 未覆盖：未读取、被截断或无法验证的内容

## 仓库上下文

- 分析模式：Full repository context analysis / Diff-only analysis
- 仓库来源：现有本地仓库 / 临时克隆 / 临时 worktree / 仅 patch
- PR 编号：
- base SHA：
- head SHA：
- merge base：
- PR 信息来源：gh / GitHub API / Git ref / 用户提供
- 完整搜索调用链：是 / 否
- 候选源码文件 / 已扫描源码文件：
- 轻量级调用图：定义数 / 调用点数 / 调用边数
- 全项目源码扫描完成：是 / 否；若否，说明超时、上限、解析失败或截断
- 未解析的 Symbol：
- 未深入检查的文件：

Diff-only 时必须写明：`未获取完整仓库，无法确认所有间接调用方和完整回归范围。`

## 改动与需求摘要

- 代码事实：有直接证据的行为变化
- 需求推断：仅 Mode A，附置信度
- 需求结论：Mode B，概括需求与实现匹配情况

## 回归范围

- 核心回归：与改动共享入口、状态、接口或数据的流程
- 定向回归：具体消费者和相邻边界
- 可不回归：仅在有明确隔离证据时列出

### 疑似超范围实现

列出没有需求依据的用户可见行为或高风险技术变更，并说明判断证据。

## 建议执行

列出仓库中实际存在的测试文件或命令。未执行时明确写“未执行，仅建议”。

## 待确认与限制

- 待确认：会改变测试预期或发布决策的问题
- 分析限制：缺失需求、动态配置、外部系统、截断 diff 等
